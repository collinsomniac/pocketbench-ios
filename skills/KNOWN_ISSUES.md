# Active limitations (2026-09-22)

- **Chat first-inference reload remains unresolved.** The user reports Qwen3 1.7B reached model-ready in the original Chat interface but Safari reloaded upon the poetry prompt. Later Chat 0.2.0 also reloaded despite using the known-good 0.6B diagnostic request shape. Safari provided no captured process-kill reason; neither OOM, a WebGPU compiler bug, nor a UI exception is established. Build **0.2.1** exposes the newly verified Llama 3.2 1B `q4f16_1` reference inside the *existing* Chat route and preserves its catalog-default context setting, rather than silently replacing it with 1,024. It also restores prior 0.2.0 session checkpoints. Mocked inference tests passed, but **this version has not yet completed real iPhone Chat inference**. See [`CHAT_LAB.md`](CHAT_LAB.md).
- **Two independent diagnostic success controls:** In `website/ai.html` WebLLM 0.2.85 dedicated worker, user-exported Qwen3 0.6B completed a 64-token stream in 1,447 ms (63 model-reported tokens; 48.72 decode tok/s; output mainly `<think>`). User-exported Llama 3.2 1B completed all four probes; the nominal 64-token stream yielded **50 reported tokens** in 3,857 ms (first text 878 ms, reported decode 16.89 tok/s) and returned a complete noun list. These different outputs/tokenizers and cache states are not a controlled model-speed ranking. One-token output can be nonempty when WebLLM usage reports zero tokens. See [`EVIDENCE.md`](EVIDENCE.md).
- **WebLLM runtime lead:** [mlc-ai/web-llm#844](https://github.com/mlc-ai/web-llm/issues/844) reports a Qwen3 prefill/GPU shape-cache regression beginning near 0.2.83 on Windows AMD. Do **not** attribute the iPhone reset to it without a matched runtime/compiled-library experiment.
- **GGUF first load unresolved:** A 105,454,144-byte SmolLM2 Q4_K_M was cached; wllama 3.6.1 aborted during initialization and mishandled a non-string abort payload. The consolidated GGUF page removed a separate import-map self-reference but successful iPhone GGUF inference is unverified.
- **Deployment:** GitHub Pages has been deployed from `main` branch root; root `index.html` redirects into `website/`. Source-level verification and mock tests do not establish live Pages publication or Safari performance. Retired experimental pages remain on archive branch `archive/pre-two-folder-cleanup-2026-09-22` and some throughput-page links may be stale.

Keep only `website/` and `skills/` as directories, repair existing slugs in place, and do not claim the Chat crash is fixed until a completed user-exported Chat run demonstrates it.
