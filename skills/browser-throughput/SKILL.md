# Maximum useful browser throughput

Read [`../../AGENT_PERFORMANCE_SKILL.md`](../../AGENT_PERFORMANCE_SKILL.md) for procedure and [`../../PERFORMANCE_FIELD_GUIDE.md`](../../PERFORMANCE_FIELD_GUIDE.md) for the evidence ledger, techniques, architectural decision table and research links. For client-side inference read [`../../AI_MOBILE_FIELD_GUIDE.md`](../../AI_MOBILE_FIELD_GUIDE.md), [`../../AI_CRASH_DIAGNOSIS.md`](../../AI_CRASH_DIAGNOSIS.md), [`../../AI_CONTEXT_EXPERIMENT.md`](../../AI_CONTEXT_EXPERIMENT.md), [`../../BROWSER_INFERENCE_STACK.md`](../../BROWSER_INFERENCE_STACK.md) and [`../../WLLAMA_IMPORT_REPAIR.md`](../../WLLAMA_IMPORT_REPAIR.md). Never invent an unmeasured speedup.

**Goal:** maximize correctly completed computational units per wall second for the requested output contract. Never silently impose 60/120 FPS caps or reframe uncapped compute as display smoothness. Separate solver rate, GPU-queue-completed iterations, sampled output change, draw submissions and independently measured display refresh. Offscreen and GPU-resident work are first-class architectures: measure avoided transfers and presentation coupling alongside extra passes.

**Process:** (1) Define completed unit, correctness tolerance and consumer: GPU field, each texture, sparse features, CPU-readable image, or visible presentation. (2) Probe actual deployment: API/feature and device limits, dimensions/DPR, extensions, worker scheduling, origin isolation, device loss. (3) Establish equivalent JS/Wasm/WebGL/WebGPU controls where expressible. (4) Collect warmed paired repeats, bounded queue-completed batches for uncapped throughput, sampled pass timestamps, output observation and reference checks. (5) Locate dominant algorithm, transfer, memory, overdraw, CPU encoding, synchronization, allocation, raster or presentation cost. (6) Change one variable, check equivalence and completed throughput, record regressions. (7) Report measured scope, uncertainty and next discriminating experiment.

**Architectures:** fluid solvers typically advance ping-pong GPU textures offscreen then separately render dye; particle integration uses resident GPU state, with neighbor search/sorting for SPH/PIC-FLIP. Browser games reuse offscreen passes for shadows, reflections and postprocessing; offscreen is not an intrinsically faster shader. Wasm runs on CPU, with SIMD and threads only where available; WebGPU exposes compute/storage and WebGL2 supports shader/FBO techniques. Apple tile GPUs reward thoughtful load/store and pass lifetimes, but browser WebGPU does not expose direct native Metal memoryless control. Prefer GPU-resident intermediates to unnecessary CPU readbacks.

**Mobile AI:** distinguish third-party author-reported, phone-measured and native-app results. A WebGPU Gemma author reports 101.1 tok/s for Gemma 3 270M and 34.4 tok/s for 1B on an iPhone 17 Pro Max; not PocketBench or equal-workload results. Explicit tap before downloading model weights. Test exact runtime+model+quantization+context, first vs cached load, worker vs main, actual usage tokens, first text, reported prefill/decode, output quality, long prompts, sustained performance and failures. Do not equate stream chunks with tokens, catalog estimates with actual memory, WebGPU with WebNN/Neural Engine, or native Core ML speed with browser speed. Prefer GPU-resident weights, activations, KV and bounded temporary memory where validated.

**PHONE-MEASURED AI control (September 21, 2026):** WebLLM 0.2.85 SmolLM2-135M-Instruct-q0f16-MLC generated text in an iPhone WebGPU worker across four probes: model-reported decode 51.55 tok/s (16-token streamed request), 46.81 tok/s (64-token streamed); first text 128/132 ms. Sequential short probes, not sustained or randomized. One-token output had four characters but API reported zero completion tokens; retain discrepancy. The Qwen3 0.6B first-inference crash in WebLLM remains unresolved.

**Diagnose inference:** checkpoint before awaited work; vary model, context, execution path or request shape one at a time. The prior WebLLM crash can be reproduced with Qwen3 0.6B in [`../../ai-context.html`](../../ai-context.html); export restored checkpoint after a reload before attempting a second configuration. Lower context is a hypothesis, not a proven fix. No automatic crash-loop retries. A page reload is not an iOS OOM diagnosis.

**Independent GGUF path — catalog hotfix 1.3, NOT yet real-device inference-validated:** use [`../../ai-wllama.html`](../../ai-wllama.html), wllama **3.6.1**, SmolLM2 Q4_K_M (~105 MB) CPU-only first, then Qwen3 0.6B Q4_K_M (~484 MB) CPU-only, then four GPU layers and maximum GPU offload separately. These GGUF weights differ from WebLLM artifacts. A September 22 phone JSON exposed HTTP **404** for the old SmolLM2 URL after runtime import and cache inventory; **no weights or inference ran**. The old TensorBlock model card lists Q4 but its actual current Files tree does not. Catalog now points to `QuantFactory/SmolLM2-135M-Instruct-GGUF/SmolLM2-135M-Instruct.Q4_K_M.gguf` and `gvij/qwen3-0.6b-gguf/qwen3-0.6b-q4_k_m.gguf`, each checked against its actual repository tree. Before shipping model choices, verify exact filenames, publisher, revision and sizes against live artifact listings, not just model-card examples or npm development-tree versions. Run `POCKETBENCH_VERIFY_HF=1 node tools/check-model-catalog.mjs` when network is available: metadata only, no model weights. HEAD HTTP 404/410 must fail fast without downloading; a failed HEAD due to CORS is not proof GET will fail. Preserve selected URL, actual error and checkpoint. A working HEAD is **not** proof of actual GET, OPFS, Wasm startup or inference. GitHub Pages cannot directly invoke native CUDA, Metal/MPS, Core ML or the Neural Engine; browser paths are WebGPU and CPU Wasm. See repair log for the measured failure and current validation limits.

**Known phone GPU results, NOT universal:** WebGPU fused 65,536 particles × 2 steps, small 768×390 observed offscreen target ~1,199 queue-completed iterations/s; large 880×1738 ~1,000/s batch16 and ~1,035/s batch64; 262,144 × 8 compute-only ~2,212 iterations/s without images. Short tests with 1.6s warmup and sparse two-patch observation, not complete-image uniqueness or display FPS. Main-thread and relayed-worker lightweight graphics submitted ~120 draws/s while native worker rAF was ~58/s. Origin previously lacked cross-origin isolation/SAB; re-probe.

**Output:** concise evidence-backed architecture choice and falsifiable experiment. Update evidence ledger only from verified reports; keep hypotheses separate. Respect resource budgets, device memory, foreground and thermal behavior, and the user's output contract.
