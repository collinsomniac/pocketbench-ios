# Maximum useful browser throughput

Read [`../../AGENT_PERFORMANCE_SKILL.md`](../../AGENT_PERFORMANCE_SKILL.md) as the operating procedure and [`../../PERFORMANCE_FIELD_GUIDE.md`](../../PERFORMANCE_FIELD_GUIDE.md) for the full evidence ledger, 20 optimization techniques, architecture decision table, fluid walkthrough, caveats, and research links. **For client-side inference, read [`../../AI_MOBILE_FIELD_GUIDE.md`](../../AI_MOBILE_FIELD_GUIDE.md), [`../../AI_CRASH_DIAGNOSIS.md`](../../AI_CRASH_DIAGNOSIS.md), and [`../../AI_CONTEXT_EXPERIMENT.md`](../../AI_CONTEXT_EXPERIMENT.md).** If those files are unavailable, apply the core steps below. Do not invent an unmeasured speedup.

**Goal:** maximize correctly completed computational units per elapsed wall second for the requested output contract. Never silently impose 60/120 FPS caps or reframe an uncapped compute task as display smoothness. Separate physics/solver rate, GPU-queue-completed iteration rate, sampled output change, draw-submission rate, and independently measured physical display refresh. **Offscreen and GPU-resident computation are valuable first-class architectures: measure avoided transfers/presentation coupling and actual extra passes instead of treating them as suspect.**

**Process:** (1) Define completed unit, correctness tolerance and required consumer: latest GPU field, every intermediate texture, only sparse features, CPU-readable pixels, or visible presentation. (2) Probe the actual deployment: API/feature availability, adapter *and device* limits, dimensions/DPR, extensions, worker scheduler, origin isolation and lost-device events. (3) Establish equivalent JS/Wasm/WebGL/WebGPU controls where expressible, including transfers, uploads, render and output requirements. (4) Collect raw timings with warmed paired repeats, bounded GPU-queue-completion batches for uncapped throughput, asynchronously sampled pass timestamps, observations and reference-state checks. (5) Locate the dominant cost: algorithmic complexity, transfer, memory traffic/locality, overdraw, CPU encoding, synchronization, allocation, rasterization or browser presentation. (6) A/B one targeted technique, verify numerical/visual equivalence and end-to-end unit throughput, document losses. (7) Report exact workload, measured scope, confidence, next discriminating test.

**Architecture pointers:** fluid solvers usually advance ping-pong GPU textures offscreen and render the resulting dye/mesh separately; particle integration uses resident GPU state, with neighbor search/sorting required for SPH/PIC-FLIP; browser games use offscreen passes for shadow/reflection/postprocessing/reuse, not inherently faster shaders; Wasm runs on CPU, with SIMD and threads only if the deployed origin permits them; WebGPU offers compute/storage, WebGL2 offers shader/FBO techniques and may outperform WebGPU on a given driver. On Apple tile GPUs optimize load/store and transient pass lifetimes portably but do not claim direct native Metal memoryless access from WebGPU. Prefer GPU-resident intermediates to repeated CPU round trips.

**Mobile AI / LLM route:** distinguish external author-reported results, actual phone-specific LLM results, and native iOS app results. A separate WebGPU Gemma author reports 101.1 tok/s for Gemma 3 270M and 34.4 tok/s for 1B on an iPhone 17 Pro Max; these are *not* PocketBench measurements or equal-workload WebLLM comparisons. Load model weights only after explicit user action. Test exact runtime+model+quantization+context; first load vs cached load; worker vs main; model-reported prompt/completion tokens; first-visible-text time vs model-provided prefill/decode speeds; model quality and failures; longer prompt and sustained runs. Never count stream chunks as tokens, treat catalog VRAM as actual RAM, assume WebGPU implies usable WebNN/Neural Engine, or import native Core ML tok/s as browser results. Prefer GPU-resident KV/activations/weights and minimal CPU readback when measurements support the pipeline.

**PHONE MEASURED AI control (2026-09-21):** a user-exported WebLLM 0.2.85 diagnostic confirms SmolLM2-135M-Instruct-q0f16-MLC generated text successfully in a dedicated iPhone WebGPU worker for all four probes. Model-reported decode: 51.55 tokens/s for the 16-token streamed request and 46.81 tokens/s for the 64-token streamed request; first text 128/132 ms respectively. These are four short *sequential* probes, not sustained or randomized comparisons. A one-token request returned four characters but reported zero completion tokens: flag the inconsistency, do not silently reinterpret it as zero output. A successful small model does **not** clear the Qwen3 0.6B first-inference crash. See `AI_CONTEXT_EXPERIMENT.md` for exact evidence and context-override follow-up.

**First-inference failure procedure:** preserve the successful small-model control; vary only one of model, context reservation, execution path, or request shape at a time. First attempt Qwen3 0.6B worker with catalog-default context and one token in [`../../ai-context.html`](../../ai-context.html); if it resets, reopen *the same page* and export the persistent checkpoint before another load; compare one-token inference with the same model and a 1,024-token context. Do not assume reduced context will fix a compiler or GPU fault. Distinguish nonempty text from WebLLM's model-reported token count; persist a stage before awaited GPU work. No automatic crash-loop retries. The older [`../../ai-diagnose.html`](../../ai-diagnose.html) and full [`../../ai-bench.html`](../../ai-bench.html) remain controls. A page reset is not an iOS OOM diagnosis.

**Known device GPU evidence, NOT universal:** 2026-09-21 user iPhone, WebGPU fused 65,536 particles × 2 steps, observed small 768×390 offscreen target: ~1,199 queue-completed iterations/s; observed large 880×1738: ~1,000/s batch16 and ~1,035/s batch64; heavy compute-only 262,144 × 8: ~2,212 iterations/s without images. These are short runs with 1.6 s warmup and sparse two-patch observation, not full-image uniqueness or display FPS. Main-thread and relayed-worker lightweight graphics reached ~120 draw submissions/s while native-worker rAF was ~58/s. Current origin previously lacked cross-origin isolation and SAB; re-probe. Full provenance and limitations are in the field guide.

**Output:** concise evidence-backed decision and a falsifiable experiment, not a generic checklist or 'optimize for 120 Hz' conclusion. Update the evidence ledger only from verified reports; keep hypotheses separate. Respect device resource limits, memory budgets, foreground/thermal behavior and actual user output semantics.
