# PocketBench: verified device findings and provenance

All figures below are user-exported short iPhone Safari-context experiments in September 2026, not a universal Apple GPU specification. Original JSON exports live in the conversation; the compact observed report is preserved as [`observed-summary.json`](observed-summary.json). The earlier source and experimental pages are on archive branch `archive/pre-two-folder-cleanup-2026-09-22`.

## GPU compute and rendering
- 65,536 dual-attractor particles × 2 integration steps, 768 × 390 offscreen output with sparse per-iteration sample capture: ~1,199 GPU-queue-completed iterations/s over ~2.5 s after ~1.6 s warmup.
- Same particle workload, 880 × 1738 offscreen output: ~1,000 observed iterations/s (batch 16) and ~1,035/s (batch 64). Two sampled patches were taken between clears; not every complete image was captured and no frames were presented.
- 262,144 particles × 8 steps, compute only: ~2,212 queue-completed iterations/s. No image per iteration.
- Lightweight WebGL2 and WebGPU submissions: main-thread rAF ~120/s, native worker rAF ~57–58/s, main-thread-paced worker relay ~120/s. These counts are submissions, not physical display measurements.
- Fusion for 262,144 × 8 compute-only was roughly 5.4× shorter GPU compute pass in one relay suite (2.106 vs 0.390 ms), with different behavior under visible rendering. Do not extrapolate a compute-pass timestamp into end-to-end presented FPS.

## Local inference
- **2026-09-22 newest successful model-family control:** User export `pocketbench-ai-diagnostic 3.json` (467 lines): WebLLM **0.2.85**, `Llama-3.2-1B-Instruct-q4f16_1-MLC`, dedicated WebGPU worker, catalog-default context, reported adapter Apple. 22 parameter-cache chunks reached ~664 MB fetched and loaded; loading began at 23:16:26.253Z and model-ready was recorded at 23:16:51.951Z (~25.7 s including network and initialization). All four fixed probes completed, no recorded errors: 1-token nonstream **1,909 ms**, 4-token nonstream **1,363 ms**, 16-token stream **1,774 ms / first text 889 ms / 15 reported completion tokens / 17.05 model-reported decode tok/s**, and 64-token stream **3,857 ms / first text 878 ms / 50 reported completion tokens / 16.89 model-reported decode tok/s**. The final 64-token response stopped at a complete 10-noun list; **it did not generate 64 actual tokens**. One-token output was `Here`, but usage reported zero completion tokens. A single successful run does not establish sustained performance or Chat UI stability.
- **2026-09-22 previous Qwen control:** User export `pocketbench-ai-diagnostic 2.json`: WebLLM 0.2.85, Qwen3-0.6B-q4f16_1-MLC, dedicated WebGPU worker, model cached and ready. One-token nonstream **271 ms**, returned `<think>` but zero completion tokens; 64-token stream **1,447 ms**, first text **137 ms**, **63** reported completion tokens, **48.7238979 model-reported decode tok/s**. Response preview contained thinking text rather than a completed useful list. Qwen and Llama have different tokenization, output lengths and cache histories; **their short-run decode rates are not a controlled architecture ranking**.
- Earlier/later Qwen Chat first-inference page reloads remain unresolved. A successful separate diagnostic **rules out categorical incompatibility**, not intermittence or a different Chat-specific failure.
- SmolLM2 135M, WebLLM 0.2.85 dedicated iPhone WebGPU worker: successful 1, 4, 16 and 64 token probes. Model-reported decode ~51.55 tok/s at 16 and ~46.81 tok/s at 64 in that report. Short requests; one-token response contained text despite zero completion-token usage.
- wllama 3.6.1 GGUF 135M: original catalog URL returned 404; corrected QuantFactory Q4_K_M artifact reached 105,454,144 cached bytes. A subsequent worker `signal.abort` had a non-string message; wllama 3.6.1's handler threw `message.replace is not a function`, leaving load pending. Root abort cause remains unknown. The 1.5 page also had a circular import-map re-export that prevented button handlers from installing. The consolidated GGUF page removes that exact import cycle and retains abort capture but is not phone-validated.
- Qwen3 1.7B and 8B in `website/chat.html` remain unverified on this iPhone, despite being catalog-listed. Catalog estimates 2,036.66 MB and 5,695.78 MB are not browser headroom readings. See [`CHAT_LAB.md`](CHAT_LAB.md).

## Confidence and next work
`website/chat.html` build **0.2.1** now offers the Llama 1B build observed in the successful diagnostic, with catalog-default context preserved and prior 0.2.0 checkpoints readable. Its Llama Chat request has **not yet been executed successfully on an iPhone**. Run Llama's identical fixed probe inside Chat, then the exact poetry prompt, export each; compare Qwen 0.6B in the same route only afterward. Repeated sustained runs, thermal/performance-state monitoring, full-image uniqueness, equal-model/quantization cross-runtime comparisons, WebGPU-vs-WebGL under equal graphics loads, and browser CPU-vs-GPU LLM throughput are unmeasured. Keep model quality separate from decode rate.
