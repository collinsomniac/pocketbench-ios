# Cross-API graphics and frame-scheduler probe

Open `graphics-probe.html` on GitHub Pages. The page automatically runs six **sequential** tests: WebGL 2 and WebGPU with main-thread `requestAnimationFrame`, worker `requestAnimationFrame`, and a main-thread `requestAnimationFrame` → worker `postMessage` relay. Each test compiles a full-screen triangle shader with the same animated fragment formula and number of iterations; the page shows the animation while the case runs.

The default is 500 ms warmup + 4 seconds measurement per test. Query parameters: `?autorun=0` disables auto-start; `?duration=1500&warmup=250&effort=8&scale=0.5` is a brief low-resolution diagnostic. Duration is clamped to 1.5–10 seconds; warmup to 0.25–2 seconds; effort selects 8, 24 or 48 iterations; scale is 0.5–1. View the current test's colored motion and export the complete JSON using **Share to Files** or **Save JSON**. Partial results are persisted in local storage after each case.

The JSON records the requested API, scheduler, canvas size, adapter/context capabilities, shader or device errors, draw-submission rate, frame-interval percentiles, JavaScript CPU submission timing, raw samples, and relay backpressure. One relay message is outstanding at most; skipped main-thread animation pulses are counted instead of queued indefinitely. Unsupported contexts are reported explicitly, not replaced silently with Canvas 2D or the other API.

**Interpretation:** A draw submission is *not* proof that the GPU completed it, that the compositor selected it, or that the display presented it. CPU draw-call timings do not measure GPU execution. We report WebGL `EXT_disjoint_timer_query_webgl2` and WebGPU `timestamp-query` feature availability but deliberately do not generate purportedly comparable GPU times here. Shader formulas are closely matched, but GLSL and WGSL compilation/driver paths are different. This is a rendering and scheduling probe, **not** a comparison of equivalent particle simulation algorithms; WebGL 2 has no WebGPU-style general compute shader. It is also not a WebGL 1 fallback test.

Keep the browser tab visible and the same Safari frame-rate flag state across tests. Tests stop when the page becomes hidden. For meaningful A/B conclusions, repeat the suite with its case order reversed in a later version and compare similar device temperatures; browser thermal sensors and real frame-presentation timestamps are not exposed here. On iOS, Safari and an app's WKWebView may have different pacing policies. UFO's disabled WebGPU option says nothing definitive about WebGPU access from a different website; this page separately tries to request an adapter, create a device, compile WGSL and submit render passes.

Documentation: [OffscreenCanvas context modes](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas/getContext), [WebGPU requestAdapter](https://developer.mozilla.org/en-US/docs/Web/API/GPU/requestAdapter), [WebGL 2 timer-query specification](https://registry.khronos.org/webgl/extensions/EXT_disjoint_timer_query_webgl2/).

Structural smoke test: `node tests/graphics-probe.mjs`. Real Safari/WebGPU behavior must be verified on-device; local headless Chromium navigation may be restricted in the assistant's environment.
